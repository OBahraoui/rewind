Add the gate to any pipeline

no token, no service, one include

The reversibility gate is a CI/CD component. On merge request pipelines its rewind-gate job fails when a change contains something that can't be undone, with the file, line and evidence in the test report. The policy is read from the merge request's base, so a change can't relax the rules checking it.

classify_action
Is this action reversible, compensatable or irreversible, and may it run hands-off?
check_paths
Which of these files are protected, and which gate rules apply to them.
rewind_policy
The whole policy in force: classes, gate rules, protected paths, privileges, review policy.
get_ledger
The ledger of a run, by run id or issue number.
list_checkpoints, explain_checkpoint
Recent checkpoints, and everything that changed since one.

Drive it from GitLab

Start a run
Label an issue {{ trigger_label }}. Rewind posts a ledger on it and keeps it current.
Undo a run
Comment /rewind on the issue or merge request (Developer role or higher).
Stop a run
Comment /rewind stop.
Status, plan
/rewind status, /rewind dry-run, /rewind help.
Accept the irreversible
Never by comment: rewind approve <run> --reason "…" with Rewind's API token.

Run Rewind on your project

about 20 minutes

You need GitLab Premium or Ultimate with the Duo Agent Platform and the Maintainer role, a pipeline that deploys with a job that fails when production is wrong, and somewhere to run Rewind's service (the scripts use Cloud Run). One Rewind instance serves one project.
